## Prerequisites

- **Node.js** >= 18.x
- **npm** >= 9.x
- A [Vercel](https://vercel.com/) account (free tier is sufficient)
- Repository hosted on GitHub, GitLab, or Bitbucket

## Vercel Deployment (Recommended)

### Initial Setup

1. **Push the repository** to your Git provider (GitHub, GitLab, or Bitbucket).

2. **Import the project** in the [Vercel Dashboard](https://vercel.com/new):
   - Click **"Add New… → Project"**.
   - Select your Git provider and authorize access if prompted.
   - Choose the `cio-it-executive-dashboard` repository.

3. **Framework detection**: Vercel will auto-detect the project as a **Vite** application and pre-fill the build settings. Verify the following values before deploying:

### Build Configuration

| Setting | Value |
|---|---|
| **Framework Preset** | Vite |
| **Build Command** | `npm run build` |
| **Output Directory** | `dist` |
| **Install Command** | `npm install` |
| **Node.js Version** | 18.x (or later) |

These settings correspond to the scripts defined in `package.json`:

```json
{
  "scripts": {
    "build": "vite build"
  }
}
```

The production build is generated by Vite into the `dist/` directory, which contains static HTML, CSS, JavaScript, and asset files ready to be served by any static hosting provider.

### Environment Variables

Configure the following environment variables in the Vercel project settings under **Settings → Environment Variables**:

| Variable | Description | Required | Default |
|---|---|---|---|
| `VITE_APP_TITLE` | Dashboard title displayed in the header | No | `CIO IT Executive Dashboard` |
| `VITE_API_BASE_URL` | Base URL for API requests (for future backend integration) | No | _(empty, uses relative paths)_ |
| `VITE_APP_ENV` | Environment mode (`development`, `staging`, `production`) | No | `development` |

**Important notes:**

- All client-side environment variables **must** be prefixed with `VITE_` to be exposed to the application at build time. This is a Vite requirement.
- Environment variables are embedded into the built JavaScript bundle at build time. They are **not** available at runtime. Changing an environment variable requires a rebuild and redeployment.
- Vercel allows you to set different values per environment (Production, Preview, Development). Use this to configure `VITE_APP_ENV` appropriately:
  - **Production**: `VITE_APP_ENV=production`
  - **Preview**: `VITE_APP_ENV=staging`
  - **Development**: `VITE_APP_ENV=development`

To set environment variables:

1. Navigate to your project in the Vercel Dashboard.
2. Go to **Settings → Environment Variables**.
3. Add each variable with the appropriate value and select the target environments (Production, Preview, Development).
4. Click **Save**.

### SPA Rewrite Configuration

The project includes a `vercel.json` file at the repository root that configures single-page application (SPA) routing. This ensures that all routes are rewritten to `index.html`, allowing client-side routing to handle navigation:

```json
{
  "rewrites": [
    {
      "source": "/((?!assets/).*)",
      "destination": "/index.html"
    }
  ]
}
```

This configuration:

- Rewrites all incoming requests to `/index.html` **except** requests to the `/assets/` directory (which contains Vite-generated static assets like JS, CSS, and images).
- Ensures that deep links (e.g., bookmarked URLs or shared links) work correctly by letting the client-side router handle the path.
- Is automatically picked up by Vercel during deployment — no additional configuration is needed.

## CI/CD — Automatic Deploys

### Production Deploys

When the Vercel project is connected to your Git repository, **production deployments are triggered automatically** on every push to the `main` branch (or whichever branch is configured as the production branch in Vercel).

**Workflow:**

1. A developer merges a pull request into `main` (or pushes directly to `main`).
2. Vercel detects the push event via the Git integration webhook.
3. Vercel runs the build pipeline:
   - Installs dependencies: `npm install`
   - Builds the project: `npm run build`
   - Deploys the contents of `dist/` to the production domain.
4. The new version is live at the production URL (e.g., `https://your-project.vercel.app`).

**Recommended branch protection rules:**

- Require pull request reviews before merging to `main`.
- Require status checks to pass (Vercel provides build status checks automatically).
- Prevent force pushes to `main`.

### Preview Deployments

Vercel automatically creates **preview deployments** for every push to any branch other than the production branch, and for every pull request.

**Workflow:**

1. A developer pushes a feature branch or opens a pull request.
2. Vercel creates a unique preview deployment with a dedicated URL (e.g., `https://your-project-<hash>.vercel.app`).
3. The preview URL is posted as a comment on the pull request (GitHub) or as a commit status.
4. Reviewers can visit the preview URL to test the changes in a production-like environment.
5. Each subsequent push to the same branch updates the preview deployment.

**Preview deployment characteristics:**

- Uses the **Preview** environment variables configured in Vercel (e.g., `VITE_APP_ENV=staging`).
- Runs the same build command (`npm run build`) and output directory (`dist`) as production.
- Preview deployments are automatically cleaned up by Vercel after the branch is deleted or the pull request is closed.
- Preview URLs are not indexed by search engines (Vercel sets `X-Robots-Tag: noindex` headers).

**Running tests before deploy (optional):**

To run tests as part of the CI pipeline before Vercel builds, you can add a GitHub Actions workflow or use Vercel's **Ignored Build Step** setting. For example, create `.github/workflows/ci.yml`:

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 18
          cache: npm
      - run: npm ci
      - run: npm run lint
      - run: npm test
```

This ensures that linting and tests pass before the Vercel deployment proceeds. Vercel will still build independently, but the GitHub status checks will block merging if tests fail.

## Manual Deployment

If you prefer to deploy without Vercel, or need to deploy to a different static hosting provider (e.g., Nginx, Apache, Cloudflare Pages, Netlify, AWS S3 + CloudFront):

### 1. Build the project

```bash
npm install
npm run build
```

### 2. Serve the `dist/` directory

The `dist/` directory contains all static files needed to serve the application. Upload or serve this directory using your preferred hosting solution.

### 3. Configure SPA routing

Ensure that your hosting provider rewrites all routes to `index.html` for client-side routing support. Examples:

**Nginx:**

```nginx
server {
    listen 80;
    server_name your-domain.com;
    root /path/to/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
}
```

**Apache (.htaccess):**

```apache
RewriteEngine On
RewriteBase /
RewriteRule ^assets/ - [L]
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule . /index.html [L]
```

**Netlify (_redirects):**

```
/*    /index.html   200
```

**Cloudflare Pages:**

Cloudflare Pages handles SPA routing automatically for single-page applications. No additional configuration is needed.

### 4. Set environment variables

When deploying manually, create a `.env` file before building (or set environment variables in your CI/CD pipeline):

```bash
cp .env.example .env
# Edit .env with production values
```

Then run `npm run build` — Vite will embed the `VITE_*` variables into the bundle at build time.

## Troubleshooting

### Build fails with "out of memory"

Increase the Node.js memory limit:

```bash
NODE_OPTIONS="--max-old-space-size=4096" npm run build
```

In Vercel, set the `NODE_OPTIONS` environment variable to `--max-old-space-size=4096`.

### Routes return 404 on page refresh

Ensure SPA rewrite rules are configured correctly. See [SPA Rewrite Configuration](#spa-rewrite-configuration) above. The `vercel.json` file handles this automatically for Vercel deployments.

### Environment variables not available in the app

- Verify that all client-side environment variables are prefixed with `VITE_`.
- Environment variables are embedded at **build time**, not runtime. After changing a variable, you must rebuild and redeploy.
- In Vercel, ensure the variable is assigned to the correct environment (Production, Preview, or Development).

### Assets not loading (404 on JS/CSS files)

- Verify that the `dist/` directory is set as the output directory.
- Ensure that the SPA rewrite rule excludes the `/assets/` path (the default `vercel.json` configuration handles this).
- Check that the `base` option in `vite.config.js` is set correctly (defaults to `/`, which is correct for root-level hosting).

### Preview deployment shows stale content

- Push a new commit to the branch to trigger a fresh preview build.
- Clear your browser cache or open the preview URL in an incognito window.
- Verify that the correct environment variables are set for the Preview environment in Vercel.
